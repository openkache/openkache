# OpenKache protocol

`openkache-protocol` is the small Rust wire-primitives crate shared by clients
and servers using the still-unpublished, evolving protocol-v1 draft profile.

## Purpose

The crate owns transport negotiation constants, canonical `vu128` helpers,
opaque request/response framing, payload limits, and reusable byte-layout
primitives. Request and response contracts deliberately do not live here: each
API module chooses its code assignments and wire layout, implements its codecs,
and registers its handler/client projection. No API adapter or operation table
is generated by this crate.

The [wire protocol specification](SPEC.md) defines transport negotiation,
envelope bytes, generic framing rules, and malformed-input handling. API
modules own operation semantics, status/result meanings, and retry policy.

## Commands

From the repository root:

```bash
bun protocol/generate.ts
OPENKACHE_GENERATION_CHECK=1 bun protocol/generate.ts
nix develop -c bazel build --lockfile_mode=error //protocol:openkache_protocol
```

Generation requires Bun and the Smithy CLI on `PATH`. The repository's Bazel
rule invokes the wire generator automatically before compiling the protocol
crate. Client-language generation is a separate, client-owned workflow; it
must not be used to define or generate this transport contract.

## Usage

Encode or decode an opaque response through the shared frame type:

```rust
use openkache_protocol::Response;

let response_bytes = [0x00, 0x04, b'P', b'O', b'N', b'G'];
let response = Response::decode(&response_bytes)?;
assert_eq!(response.code, 0x00);
```

Incremental transports can use `Response::decode_header` and
`Response::frame_len` to determine how many bytes a complete response
requires without duplicating variable-integer parsing.

## Core components

- `model/openkache.smithy` is the canonical source for transport-visible
  framing constants and the payload ceiling. API-specific serialization is
  implemented beside the API and is not inferred here.
- `wire.ts` owns AST extraction and deterministic rendering of the transport
  constants used by the runtime.
- `generate.ts` emits only those transport constants. Client generators may
  consume the model for language surface conveniences, but they do not define
  the server's wire contract or generate adapters.
- `Response` and `ResponseFrame` validate and encode complete opaque response
  frames; `ResponseHeader` supports bounded incremental reads.
- `FieldSequence`, `DenseFields`, and `OptionalValueCodec` provide byte-level
  layout primitives without assigning meaning to fields.
- `ProtocolError` classifies malformed, oversized, and invalid-layout frames.
- `SPEC.md` defines the implementation-independent contract.

## Configuration

Transport framing constants and the payload ceiling are compile-time
definitions sourced from the wire Smithy model. Change those values in
`model/openkache.smithy` and regenerate. Code/status assignments, fixed field
widths, flag masks, request/response layouts, and status/result projection
belong to the API module that owns that contract.
